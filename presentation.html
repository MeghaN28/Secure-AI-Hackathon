Anticipated Questions

Addressing key questions about Q-Shield Agent's value and differentiation.

❓ When we already have a GitHub workflow, what is the use of the agent?

The workflow is infrastructure; the agent is intelligence.

  • Workflow orchestrates steps cannot reason or correlate
  • Agent synthesizes findings into actionable narrative
  • Self-validates output through guardrails

❓ Won't GitHub Copilot do the same thing?

Copilot is a generalist with no access to your security context.

  • No CBOM, SonarQube, or PQC rule ingestion
  • No RAG retrieval from NIST standards
  • Cannot produce governance artifacts (scores, waves, compliance)

❓ Is the agent taking action or just giving recommendations?

It enforces blocks PR merges when readiness score is below threshold.

  • Security gate is a concrete enforcement action
  • Outputs structured recommendations (algorithms, effort, owners)
  • Auto-patching excluded crypto migration requires human judgment

Key Limitations

What Q-Shield Agent does not cover important for honest assessment.

⚠️

CBOM Completeness

The agent only sees cryptographic assets present in the CBOM input. If the CBOM scanner misses a dependency, Q-Shield won't detect it.

🤖

LLM Accuracy

Despite guardrails, LLM outputs may still contain imprecise language. Guardrails catch structural issues not subtle semantic errors.

🔌

External API Dependency

Report generation requires Mistral API access. If the API is unavailable or rate-limited, the pipeline step will fail.

📦

No Auto-Remediation

Q-Shield recommends fixes but does not automatically apply code changes. Engineers must implement the migration manually.

🧪

Static Analysis Scope

Cryptographic usage detected at build/config time only. Runtime-negotiated algorithms (TLS handshakes, dynamic key selection) are not covered.

📚

Knowledge Base Currency

RAG knowledge is limited to the NIST PDFs in the repository. New NIST publications require manual ingestion to update guidance.
